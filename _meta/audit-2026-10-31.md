# Audit — 31 October 2026: results

A review of security, performance and code quality, done on 31 October 2026 when the app was at
1.7.x. This file records every finding and what became of it. All are resolved as of 1.14.0
(1 November 2026). One was settled by a decision rather than a change: analytics stays opt-out.

## Security

| Finding | Outcome | Where |
| --- | --- | --- |
| Stored XSS: an imported translation was put into the quiz as HTML and could run script | Fixed. Card text always goes in as text; `test/xss.test.js` fails any `innerHTML` template that interpolates card text without `I18n.escape` | `7ecf95a` |
| No security headers | Fixed. `nosniff`, `X-Frame-Options: SAMEORIGIN`, Referrer-Policy and Permissions-Policy on every response | `3cf5890` |
| No Content-Security-Policy (inline scripts and `onclick` made one impossible) | Fixed. Scripts became modules with no inline code, then an enforced CSP was added: no `unsafe-inline`, scripts only from the app, Google's CDN, `apis.google.com` and Tag Manager. `test/app-shell.test.js` keeps the policy strict and the pages inline-free | `b9a91a4`, `33bfdcb` |
| Browser API key usable from any site | Fixed in the Google Cloud console: restricted to the app's domains; a request from another site is refused | console |
| Sign-in on `firebaseapp.com`; the redirect fallback fails where third-party storage is blocked | Fixed. Sign-in runs on yourflashcards.app itself (OAuth redirect URI added in the console) | `cc4e236` |
| Progress sync: each save rewrote the whole record, so two devices or a stale tab overwrote each other | Fixed. Only changed entries are saved and merged in; verified with two tabs | `d067ab6`, then spaced repetition `6f8324b` |
| Rules: no cap on progress history | Fixed. Capped at 20,000 entries (now the `srs` map), with tests | `3cf5890`, `6f8324b` |
| Rules: timestamps chosen by the client | Fixed. `updatedAt` must equal the server's clock | `d067ab6` |
| A HAR file with a sign-in token in the working tree | Fixed. Deleted; `*.har` is git-ignored | `.gitignore` |
| The privacy page listed a mode-switch event that never fired | Fixed. Analytics events were rewired and renamed; the privacy page lists what is sent | `b9a91a4` |
| Analytics cookies set without consent | Decided: opt-out. A cookie note under the footer, at the foot of My Cards and on the sign-in screen offers "Turn off analytics". Turning it off deletes the `_ga` cookies and Analytics never loads on that device again. Strict EU (ePrivacy) reading expects opt-in; the owner chose opt-out knowingly | `f3321dd`, `6bdcdf5` |

## Performance

| Finding | Outcome | Where |
| --- | --- | --- |
| Quadratic shuffle (21 ms at 800 cards) | Fixed. Weighted shuffle in one pass and a sort; later replaced by the spaced-repetition queue and a Fisher-Yates shuffle | `3cf5890`, `6f8324b` |
| One database read per card on every load (800 with the starter decks) | Fixed. A collection's cards live in its document: one read per collection. Imports are a single atomic write; word edits are transactions | `3342949` |
| Progress record rewritten in full every 2 seconds | Fixed with the sync finding: only changed entries are written | `d067ab6` |
| About 25 files revalidated on every page load | Fixed. The service worker serves the app from a versioned cache; the second load of a preview deploy fetched nothing and was ready in about 40 ms. A pre-deploy check stops a deploy that changes files without raising the version | `83b9014` |
| Fonts loaded through a CSS `@import` chain | Fixed. Preconnect plus `<link>` in each page; the Firebase SDK is preloaded too | `83b9014` |
| Small items: the version lookup fetched `/sw.js`; a cache-manager banner; a style lookup and debug log per quiz question; forced long polling | Fixed. The version is a module constant tested against the cache name; the banner, the debug code and the forced transport are gone | `b9a91a4`, `83b9014` |

## Not changed

  off by a page reload. This is browser noise, not an error in the app.

## Follow-up re-check (1 November 2026)

A second review session re-verified every finding against the live site (the injection no longer
runs, the headers and CSP are served on both hosts with no violations, the API key refuses foreign
referrers, 93 tests pass) and raised five notes on the new code:

| Note | Outcome | Where |
| --- | --- | --- |
| The deployed CSP allowed the emulator addresses (`127.0.0.1:8080`, `:9099`) | Fixed. `npm run dev` generates `firebase.dev.json` with them; the deployed policy has none, and a test keeps it that way | 1.14.2 |
| 5,000 cards don't guarantee a collection fits Firestore's 1 MiB (worst case about 3.7 MB) | Fixed. The cards' size is measured before every write; past about 1 MB the user gets a translated "too long, split it" message instead of Firestore's | 1.14.2 |
| Every word edit rewrites the whole collection's card list | Accepted. The cost of one read per collection; small at this app's scale | — |
| The XSS test only checked `innerHTML` template literals | Fixed. Every `innerHTML`/`outerHTML` assignment must be empty, translation text, or a reviewed sink listed in the test; `insertAdjacentHTML` and `document.write` are banned | 1.14.2 |
| The service worker won't register on the local emulator in Claude's in-app browser | Not the app: it registers on production in the same pane. Noted in the system documentation | — |
